# 对战地图制作指南

[English](map-pvp-authoring.md)

这份指南写给在 Blender 等 3D 软件里制作对战（PvP）地图、再交给服主导入的作者。它按制作顺序说明尺寸、坐标、画面、地面、出生点、图标和打包，最后附交付前检查清单和常见问题。字段的完整定义见[地图与任务导入](map-import.zh-CN.md)。

导入只读取你提供的地图包，生成游戏需要的记录和资源；服主在 Manager 中登记、编译、安装客户端包并写入服务端，玩家通过服主提供的客户端包或更新获得地图。

## 1. 先定尺寸

- **单位**：1 游戏单位 = 1 厘米。`map.json` 里的坐标、高度都用游戏单位。
- **地形大小**：`terrain.half_extent` 只能是 4096、8192 或 16384，对应地形边长 81.92、163.84、327.68 米。模型、出生点、道具点都必须在地形范围内。
- **活动范围**：`terrain.play_area` 的 `half_x`、`half_z` 是可活动区域的半宽，`ceiling` 是高度上限。机体只能在活动范围内移动，看台、远景等装饰放在范围外即可。
- 参考：一张 160 米直径的场馆地图使用 `half_extent: 8192`，活动范围 `half_x/half_z: 3050`（约 61 米见方），`ceiling: 2000`，适合两队各 6 人。

## 2. 坐标与 Blender 导出

- 游戏坐标：X 向东，Y 向上，Z 向北。Blender 坐标：X 向东，Y 向北，Z 向上。用默认设置（+Y 向上）导出 glTF 后，编译器会自动换算：**Blender 的 +Y 就是游戏的北**。
- 在 Blender 里按米建模；导出前对所有物件执行“应用全部变换”，把缩放和旋转烘进顶点。`map.json` 里该物件写 `"position": [0, 0, 0]`、`"scale": 100`（米换算成厘米）。
- 支持 `.glb`，或 `.gltf` 加独立的 `.bin` 和贴图文件。包内单个文件不能超过 64 MiB，整个包不超过 512 MiB、最多 2048 个文件，最多 1024 个物件。模型和贴图很大时，选“glTF 分离”导出。
- 只支持静态三角网格：不支持骨骼、形变和动画。每个材质读取一张基础色贴图（PNG 或 JPEG，超过 2048 像素会缩小）和基础色系数；透明材质使用 `alphaMode: "BLEND"`，可配合 `doubleSided`。
- 节点名称要有意义（例如 `Floor`、`Platform_A`），后面选择地面时要用。
- **规模**：单个模型最多约一百万个顶点和一百万个三角面，编译器会按客户端的单节点上限（65535 个顶点、21845 个三角面）自动拆分。客户端是 32 位程序，可用内存约 2 GB，一张图只在进入对局时加载。参考：19 张 2048 级贴图加 49 万面草地的场馆，对局中客户端峰值约 1.4 GB；更大的图请先测试。

## 3. 画面：把光照烘进贴图

客户端只显示模型的基础色贴图，没有实时光照、法线贴图和高光。Blender 视口里看到的效果，尤其是很强的环境光或 HDRI，都不会进游戏。想要明暗、阴影和细节，就要把它们烘进贴图：

1. 给每个物件新建一套不重叠的 UV（智能 UV 投影即可）；面积很大的物件分成几块，每块一张贴图，保证地面上每个像素约 1–3 厘米。
2. 场景只保留太阳和天空光，方向与颜色和 `map.json` 的 `terrain.lighting` 一致。
3. 用 Cycles 烘焙“漫射”，勾选直接、间接和颜色，色彩管理用“标准”。阴影过黑时，可以叠加约 10% 的纯颜色烘焙作为环境底光。
4. 把烘焙结果作为新的基础色贴图，删掉原来的程序化材质后再导出。

注意：

- **法线要朝外。** 反向的面在 Blender 渲染里看不出来，烘焙时却会被烘成黑色。打开“面朝向”显示，确认看得到的面都是蓝色。
- **草和植物**可以直接用几何体：几十万面以内没有问题。纯色草叶可以按其下方地面的颜色上色，与地面衔接最自然。
- **挡镜头时变半透明**：小物件挡住镜头时会淡化，地面和宽度超过 30 米的模型默认保持不透明。需要时用 `objects[].camera_fade` 单独指定。场馆最好把墙、柱子等拆成独立物件，只让挡住镜头的部分淡化。

## 4. 地面与地形

机体并不走在模型三角面上，而是走在 257×257 的地形高度场上（格距 = `half_extent` × 2 / 256，8192 时约 64 厘米）。有两种做法：

- **只用地形**：提供 `height.png`、地表图层贴图和遮罩，由游戏绘制地形。
- **模型做地面**（推荐，用于有精细地板的地图）：在模型物件上写 `"ground": ["Floor", "Platform_A"]`，编译器在这些网格覆盖的格点取模型上表面的高度；再写 `"terrain": {"render": false, ...}` 隐藏高度场，只显示模型。

`height.png`：

- 257×257 灰度 PNG（8 位或 16 位）；黑色对应 `min`，白色对应 `max`（游戏单位）。
- **第 0 行是北边（Blender +Y），第 0 列是西边**。图层遮罩方向相同。最常见的错误是上下颠倒：人会走到地板下面，石头从地板里穿出来。可以在 Blender 里把高度图作为置换贴到平面上，对照模型检查方向。

`ground`：

- 只选应该站上去的表面：地板、平台、台阶。墙、屋顶和高大物件选进去也会变成能站的地面。
- 比主地板高出来的平台（例如草坪、看台走廊）也要一起选上，否则机体会陷进去。
- 比格距更细的起伏（小台阶、细栏杆）无法体现在行走高度上。

碰撞：

- `collision: "auto"` 为每个网格生成一个包围盒，适合独立的箱子、柱子；`"none"` 没有碰撞；也可以写 1–64 个碰撞盒（`center`、`half_extents`、`rotation_y`）。
- 整座场馆不要用 `auto`：一个巨大的包围盒会挡住整个场地。场馆用 `"none"`，墙和障碍单独写碰撞盒或拆成独立物件。

## 5. 出生点、道具点、传送台

- `spawns.team_a` 和 `spawns.team_b` 各正好 6 个；`spawns.shared` 为 1–12 个不分阵营的点；开放 `grid` 模式时还需要 `grid_respawn_a`、`grid_respawn_b`。每个点有 `position`（`[x, y, z]`，游戏单位）和 `facing`（`[x, z]` 朝向，`[0, 1]` 朝北）。
- 出生点放在可见地面上方约 200（2 米）。编译器要求至少高出地面 20，且不能在带碰撞的物件里。改了地面（例如加了 `ground`）以后，记得按新的地面重新摆放高度。
- 两队位置尽量对称，并与墙和活动范围边缘留出距离。
- `item_patterns`：`red` 和 `blue` 的组数必须相同，每组正好 8 个道具点，最多 8 组；不需要道具时两边都写空列表。道具点不能低于地面 5 以上，也不能在物件里。
- `launch_pads`（传送台）：`position` 是触发区中心（放在地面上方约 100），`target` 是落点；可选 `size`（触发立方体边长 50–1000，默认 300）和 `speed`（16–100，默认 40）。落点要在活动范围内、高于该处地面 20 以上、低于 `ceiling`，飞行路线不能穿过地形或带碰撞的物件，飞行距离 157–27081。传送台本身不可见，要“球”的外观就在同一位置放一个 `collision: "none"` 的模型。

## 6. 天空、雾和音乐

- `terrain.sky`（`zenith`、`horizon`、`ground`）决定天空颜色，`terrain.fog`（`color`、`start`、`end`，`end` 必须大于 `start`）决定远处的雾。
- `terrain.lighting`：`sun_direction` 必须指向下方（y < 0）。烘焙贴图时用同样的太阳方向，画面才统一。
- `presentation.bgm`：包内的 MP3，或游戏自带的 `{"native": "BGM\\NNNN.mp3"}`。

## 7. 图标、名称和小地图

- **名称**：`name.zh` 和 `name.en`（最多 48 个字符）。`name.en` 会以大写写在选图图标上方，建议不超过 16 个字符，只用英文字母、数字和常见标点。
- **图标**（`presentation.preview`）：只提供一张**场景图**，任意比例，建议横图、宽度不小于 480 像素，不要自己在图上写字。编译器按原版样式居中裁成 120×64，并在上方加上发光的英文名牌。
- **小地图**（`presentation.minimap`）：正方形 PNG，覆盖**整个地形**（边长 = 2 × `half_extent`），北朝上、东朝右。编译器按活动范围裁出对战雷达图并加上橙黄边框。最好用烘焙后的模型做正交俯视渲染，与游戏画面一致。
- `presentation.boundary_lines`（默认 `true`）在地形上画出活动范围边界；地形隐藏（`render: false`）时边界线也随之隐藏。

## 9. 打包与交付

- 目录结构：`map.json`，`models/`（glTF 与贴图），`terrain/`（高度图、图层与遮罩），`images/`（场景图、小地图）。
- 每次修改文件后更新 `files` 里的 SHA-256。
- `map_key` 是地图的唯一标识（3–64 个小写字母、数字、`.`、`_`、`-`），同一 `map_key` 重新登记会替换文件，并保留服主在 Manager 里改过的名称和设置。
- 把整个文件夹（或压缩包）交给服主；服主在 Manager「地图与任务导入」中登记、编译、安装客户端包、检查并应用服务端，然后重启 World/Battle 服务。

## 10. 交付前检查清单

- [ ] Blender 的 +Y 是北；已应用全部变换；`map.json` 中 `scale` 为 100。
- [ ] `height.png` 和遮罩的第 0 行是北边，并已对照模型检查方向。
- [ ] 面朝向全部正确（看得到的面是蓝色），没有反法线。
- [ ] 光照、阴影已经烘进贴图；没有依赖视口里的强环境光。
- [ ] 所有能站上去的表面都在 `ground` 里；出生点在地面上方约 200。
- [ ] `team_a`、`team_b` 各 6 个出生点；`item_patterns` 红蓝组数相同、每组 8 个点（或都为空）。
- [ ] 单个文件不超过 64 MiB，整包不超过 512 MiB；贴图不超过 2048 像素。
- [ ] 没有骨骼和动画；透明材质用 `BLEND`。
- [ ] 整座场馆没有使用 `collision: "auto"`。
- [ ] 图标是纯场景图；小地图北朝上、覆盖整个地形。
- [ ] `files` 摘要与文件一致。

## 11. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 人走到地板下面，石头从地板里穿出来 | 高度图上下颠倒，或可站立的表面没有放进 `ground`。 |
| 一部分面在游戏里是黑的 | 反法线：烘焙只照亮法线一侧。修正面朝向后重新烘焙。 |
| 游戏里比 Blender 里暗、平 | 视口用了很强的环境光或 HDRI；游戏只显示烘焙进贴图的结果。 |
| 贴近边缘时整张图变半透明 | 整座场馆是一个物件；需要 Manager 1.16.52 或更新版本编译，或给该物件写 `"camera_fade": false`。 |
| 面数很多的模型进图崩溃 | 需要 Manager 1.16.51 或更新版本编译（自动按客户端节点上限拆分）。 |
| 选图图标上没有英文名 | 需要 Manager 1.16.52 或更新版本编译；名称取自 `name.en`。 |
| 登记时报“文件超过 64 MiB” | 用 glTF 分离导出，或把大模型拆成几个物件。 |
| 出生点“低于地面” | 改了地面后没有重新摆放出生点高度；按新的地面加 200。 |
