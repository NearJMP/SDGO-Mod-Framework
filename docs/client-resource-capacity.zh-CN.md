# 客户端资源容量

[English](client-resource-capacity.md)

关闭对应游戏后，在 Mod Manager 选择 DIY 客户端，点 **客户端 LAA**。Manager 会核对已登记 32 位游戏程序的完整原版摘要，再切换 PE 标志。再次操作可以恢复原版字节。服主管理的客户端由服主提供的运行包决定。

在 64 位 Windows 上，LAA 允许 32 位游戏使用最多 4 GiB 虚拟地址空间。地图编译与导入由 64 位 Manager 处理。在 **地图与任务导入** 编译发布包，或用 **从磁盘安装地图 ZIP** 导入已有发布包。Manager 从磁盘分块校验和暂存资源，在所选客户端关闭期间完成安装。大包最多可含 32 段原生归档，归档总量最多 2 GiB。安装后重启客户端，新地图也需要应用配套服务端计划。

## 游戏运行时的 64 位资源后台

新版地图发布包的原生归档总量超过 **128 MiB** 时，清单会声明必须启用 `resource_worker` 1.0.0 和 `map_catalog` 0.8.0，玩家客户端还需配套 Mod Manager 1.16.56 或更高版本。Manager 会在编译时提示并在安装前核对。作者发布这类地图时，请确保玩家配置档启用了资源后台。

| 组件 | 依赖关系 |
| --- | --- |
| 地图与任务导入 | 带运行时声明的地图包调用资源后台。现有包沿用各自原有的加载路径 |
| 64 位 Mod Manager | 游戏从同目录启动后台进程。进程在游戏运行期间校验、解压并缓存单项资源 |
| 扭蛋、机体、副官目录 | 启用时可共用原生资源入口，需使用配套框架版本。它们自己的归档沿用原有加载路径，地图可独立安装 |
| 地图服务端策略及 LAA | 地图仍需配套服务端计划。LAA 可独立设置 |

游戏挂载带声明的地图包时启动后台。后台无法启动时，该包不会登记。已挂载后若后台中断，本局可以从原封存归档读取同一份资源。游戏对单项资源、模型格式和显卡的限制仍适用。
